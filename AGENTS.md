# Notes for coding agents

## SEO is a first-class requirement for apps/site

oxframe.dev lives on search and link previews. Every change to the site is
also an SEO change; treat a regression like a failing test.

- **Every indexable page renders `<Seo>`** (`src/lib/components/Seo.svelte`)
  exactly once: a unique title (≤ 65 chars, keyword first, "— oxframe" last)
  and a unique description (70–170 chars) saying what a searcher gets.
  Docs pages take both from `src/lib/docs.ts` via the docs layout — a new
  doc page means a new entry there with a `description`.
- **Content must be in the prerendered HTML.** Crawlers and link previews
  read the HTML before JS. Never put a page behind `ssr = false`; mount
  browser-only parts in `onMount` (see `routes/playground`), with a real
  `<h1>` and intro text in the shell.
- **One `<h1>` per page**, then `h2`/`h3` in order (restyle, don't skip
  levels). Images get meaningful `alt`. Link text says where it goes.
- **New routes go into `routes/sitemap.xml`** (docs pages are added
  automatically). `static/llms.txt` and the versioned
  `/docs/<series>/llms.txt` files are generated by `scripts/llms.ts` on
  every build, from the page list — do not hand-edit them.
- **Canonical URLs**: `https://oxframe.dev`, no trailing slash, no query.
  Query-string variants (`/playground?ex=…`) canonicalize to the base page.
- **Structured data**: JSON-LD via `<Seo jsonld>` — SoftwareApplication on
  the home page, TechArticle + BreadcrumbList on docs, WebApplication on the
  playground. Keep facts in it true (versions, URLs).
- **Social cards**: every page but the home page has its own 1200×630
  card, drawn by oxframe (the scene in `apps/site/og/`) from the page's
  title: after adding a page or changing a title, `bun run build && bun
scripts/og-images.ts` in apps/site (needs cargo) and commit
  `static/og/` and `src/lib/og.json`; e2e fails while a card is missing or
  stale. The home page keeps `static/og.png` (`bun scripts/og-image.ts`).
- **Speed is ranking**: keep heavy code (Monaco, the engine) lazy and off
  pages that don't need it.
- Non-production pages and errors are `noindex`.
- **Mobile**: nothing may scroll sideways at 320 px (e2e: "no page is wider
  than a phone screen"). Wrap rows, let wide tables and code scroll.

`apps/site/e2e/docs.spec.ts` ("every sitemap page has complete, unique SEO
metadata") enforces most of this; extend it when you add a rule.

## mcp.oxframe.dev

`services/mcp` is a read-only MCP server (Streamable HTTP, stateless, no
auth) for agents that cannot run the CLI, such as ChatGPT and the Codex
plugin directory: `docs_search`, `get_page`, `list_components`,
`get_example`. It reads `https://oxframe.dev/docs-index.json`, which
`scripts/markdown-pages.ts` writes on every site build, so it follows the
docs without a redeploy. Deployed by `.github/workflows/deploy-mcp.yml` on
changes to `services/mcp`.

## Shared videos

The playground's "Share video" renders the scene in the browser and posts
it to `/api/share` (`apps/site/worker/share.ts`): MP4 checked by its boxes,
at most 16 MB and 30 s, a JPEG poster, the scene's share link, 3 uploads a
minute per address. `oxframe publish` (CLI) posts to the same endpoint with
no share link and an optional `title` (≤ 100 characters); its page has no
playground button. Files live in R2 under `shares/<id>/` and an R2
lifecycle rule (`shares-30-days`) deletes them after 30 days; `/s/<id>` is
a `noindex` page with `og:video`. Remove one earlier with `bun
scripts/delete-share.ts <id>`.

## Migration guides

`/docs/migrate/*` show the same scene in another tool and in oxframe. The
code lives in `apps/site/src/lib/migrate/` (`x.tsx.txt`, `x.py.txt` and the
port `x.rs`, in the playground's `pub fn project()` form). After changing a
port or bumping the oxframe version in `apps/site/og/Cargo.toml`, run `bun
scripts/check-migrate.ts` in apps/site: it compiles every port and fails
unless `oxframe check` reports no issue.

## Versioned docs

**Docs never get ahead of crates.io.** The site deploys on every push to
main, so documentation of a new SDK feature lands in the same commit that
bumps `apps/site/src/lib/sdk.ts` to a version that is already published
(tag `vX.Y.Z` in oxframe-sdk, then wait for crates.io). The production build
fails if `sdk.ts` names an unpublished version
(`apps/site/scripts/crate-versions.ts`).

The docs at `/docs/…` describe the SDK version in `apps/site/src/lib/sdk.ts`
(the playground builds with the same one). Older minor versions are
snapshots at `/docs/<series>/…`; `/docs/<current series>/…` 301-redirects to
`/docs/…` (`apps/site/redirects.ts`), so version-pinned links always work.

- The version switcher lists the current docs plus the snapshots
  (`src/lib/docs-archive/`). The current docs are labelled with `sdk.ts`;
  snapshots with the newest published patch of their series from crates.io
  (`src/lib/versions.json`, refreshed by `scripts/crate-versions.ts` on every
  build, kept as is when crates.io is unreachable). The build fails when
  `src/lib/changelog.json` has no entry for `sdk.ts` (`scripts/check-changelog.ts`).
- **Every release keeps the previous docs.** Before bumping `sdk.ts` from
  the published version X (say 0.2.6) to the next one, run
  `bun scripts/archive-docs.ts 0.2.6` (a snapshot at `/docs/0.2.6/…`, links
  rewritten), then `bun run format`, then bump `sdk.ts` and update the docs.
  Older snapshots may be whole series (`0.1`) or exact versions (`0.2.1`).
  Bumping `sdk.ts` redeploys both the site and compile.oxframe.dev (new
  container image, ~30–40 min); in between the playground says it is being
  upgraded.
- `bun run sync-examples` also copies the SDK's CHANGELOG.md to
  `/changelog`. Once the release's video is attached on GitHub (the SDK's
  `release video` workflow), `bun scripts/release-media.ts` copies it to R2
  for that page.
- Archived pages are canonicalized to the current page and stay out of the
  sitemap; "API reference" links to docs.rs for the selected version.
- `scripts/llms.ts` writes `/llms.txt` for the current docs and
  `/docs/<series>/llms.txt` plus `llms-full.txt` for every archived series.
  The current series (`/docs/0.2/llms.txt` while 0.2 is current) redirects to
  `/llms.txt`, so a version-pinned link still resolves. The archive script
  runs the same generator after it snapshots a series.
